== Preparación del servidor

Los scripts de Bash y las tareas de `cron` se trabajan con tu cuenta de ASO, sin privilegios.

`cron` lanza las tareas a la hora del servidor, así que el servidor tiene que estar en la hora de España. Hacedlo una vez, desde el usuario del proyecto:

[source,bash]
----
sudo timedatectl set-timezone Europe/Madrid
sudo systemctl restart cron
timedatectl
----

`timedatectl` debe mostrar `Time zone: Europe/Madrid` y una hora local igual a la de vuestro reloj. Se reinicia `cron` para que use la nueva zona horaria.

NOTE: Cambiar la zona horaria no modifica servicios ni datos, así que no hace falta copia de seguridad.

Para la parte de PowerShell, como no trabajamos con equipos Windows, instalaremos PowerShell en el servidor del grupo. Hacedlo una vez, desde el usuario del proyecto:

[source,bash]
----
sudo snap install powershell --classic
pwsh --version
----

Después, cualquier cuenta puede abrirlo con `pwsh` y salir con `exit`.

NOTE: Instalar PowerShell añade un programa independiente y no modifica servicios ni datos, así que no hace falta copia de seguridad.

== De una orden a un guion

Un script reúne instrucciones para repetir una operación. Su utilidad depende de que los datos de entrada estén claros, los errores se detecten y el resultado se pueda comprobar. Automatizar una operación incorrecta solo permite repetir el error más deprisa.

En Bash trabajaremos variables, comillas, argumentos, condiciones, bucles y funciones. En PowerShell aprenderemos a tratar objetos, seleccionar propiedades y combinar cmdlets. Ambos permiten administrar, aunque su modelo de datos sea diferente.

== Un informe sencillo en Bash

Este script recibe como primer argumento el archivo donde guardará un informe. Si no lo recibe, utiliza `informe.txt` en el directorio actual. No requiere privilegios administrativos.

[source,bash]
----
#!/usr/bin/env bash
destino="${1:-informe.txt}"
if {
  date
  hostname
  df -h
} > "$destino"; then
  printf 'Informe guardado en %s\n' "$destino"
else
  printf 'No se pudo generar el informe\n' >&2
  exit 1
fi
----

Las comillas conservan el argumento aunque contenga espacios. La redirección reemplaza el archivo de destino. Debes elegir una ruta propia de prácticas, dentro de `~/aso-lab`, y comprobar el resultado. Este ejemplo inicial comprueba el estado final del grupo; un guion más exigente debe comprobar cada operación cuya ejecución correcta sea necesaria.

La depuración combina lectura, datos de prueba y observación. Prueba un caso normal, una ruta con espacios y un destino sin permisos de escritura, por ejemplo el directorio personal de un compañero. Documenta lo que esperabas y lo que ocurrió.

== Objetos en PowerShell

En PowerShell una canalización puede transportar objetos con propiedades. Por ejemplo:

[source,powershell]
----
Get-Process | Select-Object -First 5 Name, Id
----

El objetivo es seleccionar cinco procesos y mostrar su nombre e identificador. No los ordena por consumo. Para construir un informe útil hay que escoger qué propiedades medir y qué pregunta se quiere responder.

PowerShell en Linux no incluye todos los cmdlets de Windows: los que gestionan servicios, registro o cuentas de Windows no están disponibles. Para aprender el modelo de objetos y las canalizaciones es suficiente.

Los scripts de gestión de cuentas y directorio se retomarán cuando conozcamos esos servicios. Crear usuarios mediante un script exige el mismo cuidado con permisos y datos que hacerlo de forma manual.

== Programar una tarea

Una tarea programada necesita una acción, una identidad, un calendario y un registro del resultado. También necesita rutas y un entorno definidos: una orden que funciona en tu terminal puede fallar al ejecutarse sin tu sesión.

Cada cuenta tiene su propia tabla de tareas, que se edita con `crontab -e` y se consulta con `crontab -l`. Cada línea tiene cinco campos que indican cuándo se ejecuta y, detrás, la orden que se ejecuta:

[literal]
....
30   8   *   *   1   /ruta/absoluta/orden
│    │   │   │   │
│    │   │   │   └ día de la semana (0 - 7, donde 0 y 7 son domingo; 1 = lunes)
│    │   │   └ mes (1 - 12)
│    │   └ día del mes (1 - 31)
│    └ hora (0 - 23)
└ minuto (0 - 59)
....

`30 8 * * 1` representa una ejecución los lunes a las 08:30, según la zona horaria del servidor. En cada campo se pueden usar estos símbolos, y se pueden combinar:

[cols="1,2,3",options="header"]
|===
|Símbolo |Ejemplo |Se lee
|`*` todos |`* * * * *` |cada minuto
|`,` lista |`0 8,14 * * *` |a las 8:00 y a las 14:00
|`-` rango |`30 8 * * 1-5` |de lunes a viernes a las 8:30
|`/` cada tanto |`*/10 * * * *` |cada 10 minutos
|===

Por ejemplo, `0 8-14/2 * * 1-5` se ejecuta de lunes a viernes a las 8, 10, 12 y 14 en punto.

En lugar de los cinco campos también se puede escribir `@reboot`: la orden se ejecuta una vez cada vez que arranca el servidor.

La orden se escribe con rutas absolutas.

TIP: Para ampliar, con más ejemplos de calendarios: link:https://cubepath.com/es/docs/herramientas-de-automatizaci%C3%B3n/trabajos-cron-sintaxis-y-ejemplos-practicos[Trabajos cron: sintaxis y ejemplos prácticos^].

Para comparar, estudiaremos sobre el papel los desencadenadores, acciones y condiciones del Programador de tareas de Windows.

Programar no equivale a verificar. Revisa la ejecución, sus errores y el archivo generado; comprueba también qué sucede si el sistema estaba apagado o la operación anterior aún no había terminado.

== Práctica A · Generar y revisar un informe

Trabaja con tu cuenta de ASO, dentro de `~/aso-lab`.

. Guarda el script en un archivo de tu espacio de prácticas:
.. Crea la carpeta, si aún no existe, y entra en ella:
+
[source,bash]
----
mkdir -p ~/aso-lab
cd ~/aso-lab
----
.. Abre el editor con el nombre del archivo: `nano informe.sh`. Si el archivo no existe, `nano` lo crea al guardar.
.. Escribe o pega el script. La primera línea debe ser `#!/usr/bin/env bash`.
.. Guarda con `Ctrl+O` y confirma el nombre con `Intro`. Sal con `Ctrl+X`.
.. Comprueba que se ha guardado: `cat informe.sh` muestra su contenido y `ls -l informe.sh` muestra el archivo con su tamaño.
. Ejecútalo mediante Bash con un destino propio.
. Comprueba el contenido y repite los tres casos de prueba.
. Programa la tarea en tu `crontab` con un calendario cercano para poder comprobarla, y retírala después.
. Registra una ejecución y distingue el resultado del script del estado del planificador.
. Obtén con PowerShell los cinco procesos que más memoria usan y explica qué propiedad has utilizado.

*Entrega.* Código comentado, tabla de pruebas y ficha de la tarea: usuario, calendario, acción, registros y comprobación.
