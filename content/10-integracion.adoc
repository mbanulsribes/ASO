== Preparación del servidor

El recurso compartido se configura con Samba en el servidor Ubuntu. Los clientes serán la VM de Windows Server de la unidad 07 y el propio Ubuntu. Todo ocurre dentro de la red del grupo, así que no hace falta ninguna regla nueva en el router.

WARNING: *Copia de seguridad antes de empezar:* `sudo tar czf /root/etc-antes-u10.tar.gz /etc`. Comprobad que la copia se puede leer con `sudo tar tzf`.

Desde el usuario del proyecto:

[source,bash]
----
sudo apt install samba smbclient
sudo groupadd alumnado
sudo groupadd profesorado
sudo mkdir -p /srv/compartido/materiales /srv/compartido/entregas
----

Repartid las cuentas de ASO del equipo entre `alumnado` y `profesorado` con `usermod -aG`. Samba guarda sus contraseñas aparte de las del sistema, así que cada cuenta que vaya a conectarse necesita una contraseña de Samba:

[source,bash]
----
sudo smbpasswd -a usuario
----

Los permisos de las carpetas y la configuración de `/etc/samba/smb.conf` forman parte de la práctica: se diseñan antes de escribirlos.

NOTE: Windows Server 2025 no permite el acceso de invitado y exige firma en las conexiones SMB salientes. Por eso cada prueba se hace con una cuenta y su contraseña de Samba.

== Sistemas diferentes, recursos comunes

Una red heterogénea reúne sistemas con herramientas y modelos de administración distintos. El objetivo es que cooperen sin perder el control de identidades y permisos. En esta unidad relacionaremos conectividad, directorio, acceso remoto y recursos compartidos.

El ZIP de referencia menciona esta unidad en la programación, pero no incluye una unidad desarrollada propia. Este capítulo ofrece el recorrido inicial para completarla con las prácticas del laboratorio.

== Compartir archivos

Estudiaremos SMB mediante Samba para compartir recursos con clientes Windows y Linux, y compararemos el enfoque con NFS. No elegimos un protocolo solo porque ambos equipos estén conectados: también importan identidades, permisos, clientes y requisitos del servicio.

Compartir una carpeta no elimina los permisos del sistema de archivos. El resultado depende de la configuración del recurso y de la identidad con que se accede. Una cuenta local con el mismo nombre en dos equipos no demuestra que ambos reconozcan a la misma persona.

Un recurso de Samba se declara en `/etc/samba/smb.conf`. Este fragmento es un punto de partida, no la solución:

[source,ini]
----
[materiales]
   path = /srv/compartido/materiales
   valid users = @alumnado @profesorado
   read only = yes
   write list = @profesorado
----

Después de cada cambio, revisa la sintaxis con `testparm` y aplica la configuración con `sudo systemctl reload smbd`.

Desde los clientes:

[source,bash]
----
smbclient -L //192.168.10X.2 -U usuario
smbclient //192.168.10X.2/materiales -U usuario
----

[source,powershell]
----
net use Z: \\192.168.10X.2\materiales /user:usuario
----

== Diseñar pruebas de acceso

Antes de configurar, construye una matriz: quién puede leer, quién puede escribir y quién no debe entrar. Después prueba cada caso desde los sistemas cliente previstos.

[cols="1,1,1",options="header"]
|===
|Grupo |Materiales |Entregas propias
|Alumnado |Lectura |Lectura y escritura
|Profesorado |Lectura y escritura |Según la política del caso
|Sin autorización |Sin acceso |Sin acceso
|===

La matriz es una especificación, no una configuración terminada. Para convertirla en permisos hay que decidir estructura de carpetas, grupos e identidades. La carpeta de entregas no debe permitir por accidente modificar el trabajo de otra persona.

== Práctica A · Un recurso compartido

. Dibuja el mapa de red del grupo: aula, router, servidor Ubuntu y VM de Windows.
. Define carpetas, grupos y matriz de acceso.
. Configura los permisos de `/srv/compartido` y los recursos de Samba según tu diseño.
. Prueba lectura y escritura desde Windows con `net use` y desde Ubuntu con `smbclient`.
. Realiza una prueba con una cuenta no autorizada, por ejemplo la del proyecto sin contraseña de Samba.
. Documenta configuración, resultados e incidencias.

*Entrega.* Mapa, matriz, pruebas positivas y negativas. Que una cuenta administradora consiga entrar no demuestra que el diseño de permisos sea correcto para el alumnado.

[.plan-b]
=== Plan B · Revisar una compartición

Un recurso llamado `materiales` debe permitir lectura al alumnado. En la prueba preparada, una cuenta de estudiante crea y elimina archivos. La conectividad funciona y se reconoce la cuenta.

. Identifica qué requisito se incumple.
. Explica qué permisos y pertenencias revisarías.
. Diseña una estructura para que cada estudiante entregue archivos sin modificar los ajenos.
. Redacta pruebas desde ambos sistemas y para una cuenta sin autorización.

*Entrega B.* Matriz corregida, diseño y resultados esperados. La configuración y el acceso efectivos se verificarán en el laboratorio.
